# Production deployment research

Checked 2026-10-18 against official provider documentation.

## Recommended free architecture

Use a Render Web Service for the Flask app, a separate free Supabase Postgres project for persistent data, and an HTTPS email API such as Resend. Do not use Render Free Postgres for real event records: the free database expires after 30 days and has no backups. Render Free Web Services also spin down after inactivity and cannot send SMTP traffic on ports 25, 465, or 587.

Supabase Free provides Postgres, but projects can pause after inactivity and free projects do not receive managed daily backups. Schedule regular logical exports with `pg_dump` or the Supabase CLI and keep a copy outside the hosting service.

## Required secrets

- `SECRET_KEY`: generate locally with `python3 -c "import secrets; print(secrets.token_urlsafe(48))"` and store only in the host's environment-variable settings.
- `DATABASE_URL`: copy the Postgres connection string from the provider's Connect/Database page; do not commit it.
- `SESSION_COOKIE_SECURE=True`: this is a configuration flag, not a key. It tells browsers to send the session cookie only over HTTPS.
- `BASE_URL`: set it to the deployed HTTPS URL, such as the Render `onrender.com` URL.

## Zero-cost launch checklist

1. Create a Supabase project and copy its Postgres connection string into Render as `DATABASE_URL`.
2. Create a Render Web Service from this repository. `render.yaml` supplies the build command, Gunicorn start command, and `/healthz` health check.
3. In Render, set `ADMIN_PASSWORD` to a long unique password and set `BASE_URL` to the final HTTPS Render URL. Keep `SECRET_KEY` generated by Render; never put either secret in Git.
4. Create a Resend account, verify the sender domain or sender address, and add `RESEND_API_KEY` plus `RESEND_FROM_EMAIL`. The application uses Resend over HTTPS because Render Free blocks outbound SMTP ports.
5. Confirm `/healthz` returns HTTP 200, open the public registration page, submit a controlled test registration, and verify that the record appears in the admin dashboard.
6. For online UPI, the participant submits the bank-generated UTR. An administrator must compare it with the college bank statement and press **Verify payment**. The database update is atomic, and the receipt is sent only after verification. This is deliberately not treated as automatic bank settlement.
7. Run `scripts/backup_postgres.sh` from a machine that has `pg_dump` and copy the resulting compressed dump to storage outside Render/Supabase. Keep at least two recent copies and periodically test restoring one.

The repository does not create provider accounts, verify domains, approve UPI merchant onboarding, or store credentials automatically. Those steps require the college account owner and cannot safely be automated from source code.

## Payments

NPCI states that merchants must partner with an acquiring bank for UPI infrastructure. A plain `upi://pay` link or QR can start a payment but cannot prove settlement to this application. Automatic confirmation requires a bank or payment aggregator API, merchant onboarding/KYC, webhooks, and reconciliation.

## WhatsApp

The WhatsApp Business application is not itself an API credential. WhatsApp Cloud API requires a Meta business setup, a business phone number, access token, webhook configuration, templates for business-initiated messages, and policy compliance. Automatic outbound messages may incur applicable conversation charges; it is not guaranteed to be free merely because the WhatsApp app is free.
